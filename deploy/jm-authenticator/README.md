## Build and upload to one.com

1. In `web/`, run `npm run build`. The complete release package is `web/dist/`.
2. Confirm `web/dist/jm-authenticator/privacy/index.html` matches the source and that `navigation.js` and `branding/jm-shield.png` are present under `web/dist/jm-authenticator/`.
3. Open the one.com File Manager for `jegprofil.info` and its document root (`public_html`).
4. Upload by merging the **contents** of `web/dist/` into the document root. Never use a mode that deletes server files absent from the package. Existing Share Monitor backend files, `.htaccess` and other server components must be preserved. Do not upload this README.
5. Open `https://jegprofil.info/jm-authenticator/privacy/` over HTTPS on mobile and desktop. Check that the header logo and language selector appear, that the contents links and the privacy contact work, and that `/jm-authenticator/privacy` redirects to the trailing-slash URL.

No PHP or hosting-configuration change is required for this page.

## Open verification item

Whether iOS Keychain vault items remain after the app is deleted has not been verified on a physical device. The policy therefore states only that Keychain data *may* remain, and that users should not rely on deleting the app to erase accounts or on reinstalling it to recover them. Update the Retention section once this is verified.
